# D2-03：Telegram 收據核對與重試

日期：2026-09-25。此批延續本機辨識，補齊 Telegram 的手機操作流程；資料 schema、provider、提示版本及 Web API 契約均未改。

## 行為

- 待確認卡片新增 USD / TWD 幣別選擇，原始小計／稅／小費／折扣與 AI 幣別參考。幣別選擇不換算金額；帳戶幣別不符仍阻止確認。
- 原始明細與手動記帳金額分開，缺值不填 0；重新辨識中標明前次辨識明細。
- Bot 重新辨識先提示覆寫欄位、再確認排程；下載失敗可重試下載，沒有 AI 也可用。Web 與 Bot 使用同一個 retry service。
- 處理中僅提供進度／取消；已關閉草稿不提供修改。舊 revision、重複 update、非白名單、無效幣別及停用辨識皆有保護。原圖、舊 parse attempt 與正式交易不因重試而被改寫。

## 驗證

真實 PostgreSQL `finance_test` 隔離整合：**74 項通過**，含 5 項新情境：

1. 由實際排入的 Telegram 卡片讀取 callback，選幣別、重送 update、點舊按鈕；原始 parsed 不變，帳戶幣別不符不能入帳，餘額不變。
2. 重試提示不排工作；確認只建立一個新辨識工作，重複／舊 callback 不重排；處理中按鈕符合狀態，兩次辨識歷史均保留。
3. 無效幣別、非白名單、已取消草稿與停用 AI 的偽造按鈕不修改草稿、不入帳。
4. 照片下載連續失敗 5 次後，由卡片確認重新下載；成功保存圖片且未啟用 AI 時不誤建辨識工作。
5. 不明／明確零值顯示不同；在重試提示後人工修改，舊確認按鈕不能排工作或覆蓋新值。

Ruff / format、mypy、Alembic drift 與 OpenAPI 產生通過。測試使用合成文字、圖片、Bot ID 與解析結果；Telegram 外部傳送未在此批主動呼叫。這些測試不能代替真正 iPhone Telegram 的按鈕點擊驗收，也沒有宣稱 OCR 速度或品質因此提升。

## 本機部署

Docker arm64 API 映像建置通過；維護標記期間依序停止舊 bridge、更新 API / worker、啟動新版 bridge 並重建 Web 代理，完成後移除標記。Web `/api/health/ready` 回覆 ready，bridge heartbeat 在 60 秒內。部署前後正式交易及草稿的整列指紋一致，辨識歷程筆數與草稿狀態不變。沒有測試資料寫入正式帳本，沒有主動重新發送既有 Telegram 卡片；隔離測試資料庫已停止。

既有 Telegram 訊息不會自動改版；使用者以 `/pending` 點開待辦或傳送新收據後，可取得新版卡片。此批實機按鈕驗收保留待辦。
